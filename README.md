# Bulls and Cows

언리얼 엔진 C++로 구현한 멀티플레이 숫자 야구 게임입니다.  
플레이어가 채팅 입력창을 통해 닉네임을 등록한 뒤, 서버가 정한 3자리 정답을 제한 시간 안에 번갈아 추측하는 방식으로 진행됩니다.

## 프로젝트 정보

- 프로젝트명: `BullsAndCows`
- 주요 구현 언어: C++
- 게임 방식: 2인 이상 멀티플레이 턴제 숫자 야구
- 정답 규칙: 1~9 사이의 중복 없는 3자리 숫자
- 입력 방식: 채팅 UI 입력
- 기본 시도 횟수: 플레이어당 3회
- 기본 턴 제한 시간: 10초

## 실행 방법

1. `BullsAndCows.uproject`를 Unreal Editor에서 엽니다.
2. Play 설정에서 플레이어 수를 2명 이상으로 설정합니다.
3. 각 클라이언트에서 첫 입력으로 닉네임을 등록합니다.
4. 2명 이상 접속하면 게임이 자동으로 시작됩니다.
5. 자신의 턴에 중복 없는 3자리 숫자를 입력해 정답을 맞힙니다.

## 주요 클래스 역할

### `ABNCGameModeBase`

서버 권한으로 게임의 핵심 규칙을 관리합니다.

- 플레이어 접속/퇴장 관리
- 게임 시작, 재시작, 대기 상태 전환
- 정답 숫자 생성
- 턴 순서 결정 및 현재 턴 플레이어 안내
- 숫자 입력 검증
- Strike/Ball/Out 판정
- 승리, 무승부, 기회 소진 처리
- 턴 제한 시간 만료 처리

### `ABNCGameState`

모든 클라이언트가 공유해야 하는 시간 정보를 관리합니다.

- `TimeLimit`, `TimeElapsed` 복제
- 남은 시간 계산
- UI에서 타이머를 표시할 수 있도록 제한 시간 상태 제공

### `ABNCPlayerController`

클라이언트 UI와 서버 게임 로직 사이의 입력/출력 흐름을 담당합니다.

- 채팅 입력 UI, 알림 UI, 타이머 UI 생성
- 클라이언트 입력을 서버 RPC로 전달
- 서버에서 전달한 채팅/시스템 메시지 출력
- 닉네임 최초 등록 처리
- 일반 채팅과 정답 입력을 GameMode로 전달

### `ABNCPlayerState`

플레이어별로 유지되어야 하는 상태를 저장하고 복제합니다.

- 닉네임
- 현재 시도 횟수
- 최대 시도 횟수

### UI 위젯

- `UBNCChatting`: 채팅 입력 및 엔터 입력 처리
- `UBNCChatMessage`: 채팅/시스템 메시지 한 줄 표시
- `UPlayTimerWidget`: 현재 턴의 남은 시간 표시
- `UServerNotificationWidget`: 현재 턴, 승패, 대기 상태 등 주요 알림 표시

## 기능별 구현 내역

### 1. 턴제 진행

`ABNCGameModeBase`에서 접속한 `ABNCPlayerController`를 배열로 관리하고, `CurrentPlayerIndex`로 현재 턴 플레이어를 판단하도록 구현했습니다.

게임 시작 시 `Algo::RandomShuffle`을 사용해 플레이어 순서를 섞어 매 게임의 시작 순서를 다르게 만들었습니다. 정답 입력이 정상 처리되거나 제한 시간이 만료되면 다음 플레이어로 턴을 넘깁니다.

현재 턴이 아닌 플레이어가 숫자를 입력하면 정답 시도로 처리하지 않고 일반 채팅으로 출력되도록 분기했습니다.

### 2. 정답 생성 및 판정

정답은 `GenerateNewAnswer()`에서 1~9 사이의 중복 없는 3자리 숫자로 생성합니다.

입력값은 `IsGuessingNumberString()`에서 다음 조건을 검사합니다.

- 길이가 정확히 3자리인지
- 모든 문자가 숫자인지
- 0이 포함되지 않았는지
- 중복된 숫자가 없는지

정상적인 숫자 입력이면 `JudgeResult()`에서 Strike와 Ball을 계산하고, 둘 다 없으면 `OUT`으로 표시합니다. 3 Strike가 나오면 해당 플레이어의 승리로 판정합니다.

### 3. 채팅 입력과 정답 입력 분리

기존 채팅 입력창을 게임 입력창으로 함께 사용했습니다.

서버에서는 입력 문자열이 다음 조건을 모두 만족할 때만 정답 시도로 처리합니다.

- 게임이 진행 중일 것
- 입력한 플레이어가 현재 턴 플레이어일 것
- 입력값이 중복 없는 3자리 숫자일 것
- 해당 플레이어의 시도 횟수가 남아 있을 것

조건을 만족하지 않는 입력은 일반 채팅 메시지로 처리해, 채팅 기능과 게임 입력 기능이 동시에 동작하도록 했습니다.

### 4. 제한 시간 타이머

각 턴마다 10초 제한 시간을 적용했습니다.

`ABNCGameModeBase`에서 `FTimerHandle`을 사용해 턴 제한 시간을 시작하고, `ABNCGameState`의 `TimeLimit`, `TimeElapsed` 값을 갱신합니다. 클라이언트의 `UPlayTimerWidget`은 GameState의 남은 시간을 읽어 화면에 표시합니다.

제한 시간이 만료되면 현재 턴 플레이어의 기회를 1회 차감하고, 다음 플레이어에게 턴을 넘깁니다.

### 5. 입력 기회 제한

각 플레이어는 한 게임에서 최대 3회까지 정답을 시도할 수 있습니다.

시도 횟수는 `ABNCPlayerState`의 `CurrentGuessCount`, `MaxGuessCount`로 관리하며, 게임이 재시작될 때 모든 플레이어의 시도 횟수를 초기화합니다.

정답 입력뿐 아니라 제한 시간 초과도 기회 사용으로 처리했습니다. 모든 플레이어의 기회가 소진되면 무승부로 판정하고 정답을 공개한 뒤 새 게임을 시작합니다.

### 6. 플레이어 입장 및 퇴장 처리

플레이어가 처음 채팅 입력을 하면 해당 문자열을 닉네임으로 등록하고, 이후 GameMode의 플레이어 목록에 추가합니다.

플레이어가 2명 이상이면 게임을 시작하고, 2명 미만이면 대기 상태를 유지합니다. 게임 도중 플레이어가 입장하거나 퇴장해 플레이어 구성이 바뀌면 현재 게임을 정리하고 재시작하도록 처리했습니다.

퇴장 후 플레이어 수가 2명 미만이 되면 게임을 중단하고 대기 상태로 전환합니다.

### 7. 클라이언트 알림 UI

게임 진행 상황을 채팅 메시지와 별도의 시스템 알림으로 구분해 표시했습니다.

- 현재 턴 플레이어 안내
- 승리/무승부 결과
- 제한 시간 초과
- 게임 시작 대기
- 재시작 안내
- 각 입력 결과와 남은 시도 횟수

서버에서 각 클라이언트로 Client RPC를 호출해 동일한 게임 진행 정보를 확인할 수 있도록 구현했습니다.

## 구현 시 고려한 점

- 게임 규칙과 승패 판정은 서버의 `GameMode`에서만 처리해 클라이언트 간 상태 차이를 줄였습니다.
- 클라이언트에 필요한 시간, 닉네임, 시도 횟수는 `GameState`와 `PlayerState`를 통해 복제했습니다.
- 채팅 입력을 재사용하되, 서버에서 입력 조건을 검사해 일반 채팅과 정답 제출을 명확히 구분했습니다.
- 플레이어가 입장/퇴장해도 게임이 멈추지 않도록 대기 및 재시작 흐름을 추가했습니다.
